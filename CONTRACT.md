## Public entry, authentication, and bootstrap

The Site is public, but operational records and actions require a valid Supabase Auth session and private ARIOS profile. Entry paths are `/`, `/login/client`, `/login/team`, `/setup`, and `/portal/`. There is no ChatGPT sign-in requirement in the current ARIOS login flow, no public self-registration, and no nonfunctional password-reset button.

`POST /api/login {email,password,portal}` authenticates with Supabase, verifies Edge workspace membership, and enforces client/customer versus team/worker-or-manager on the server before issuing browser session cookies. Client JavaScript checks are not authorization. Access and refresh tokens are stored as HttpOnly, SameSite=Lax cookies, Secure on HTTPS; never localStorage. BFF refreshes an expired access token once through Supabase and clears invalid sessions. All BFF POSTs require the exact same Origin and reject cross-site requests. Logout clears local cookies even if remote revocation is temporarily unavailable.

Every Edge operational call validates the supplied user token through Supabase Auth and resolves role/domain identity from private `arios_profiles` plus current domain state. Never authorize from editable `user_metadata`. Public/publishable access does not grant direct table privileges. A user with a valid Auth identity but no matching ARIOS profile is denied.

Initial owner setup uses `/setup#code=...`; the actual one-time code is delivered privately and never committed. The setup script retains it only in memory and removes the URL fragment. `/api/bootstrap` is the deliberate prelogin exception: rate-limited, validated against a private hashed unexpired owner code and exact owner email, and atomically consumed. It creates or binds the Supabase owner identity to the existing manager without replacing migrated production records. No GET URL query carries a password or bootstrap code. New member/customer accounts are created only by an authenticated manager, with consistent Auth/profile/domain commits and recovery for uncertain outcomes.

There is no anonymous operational-data or sync exception. `/api/telegram/sync` requires an authenticated ARIOS manager. No permanent webhook or background schedule is implemented; browser manager polling is not unattended receipt. Any future unattended integration needs its own explicit scoped authorization and verification before scheduling.

## Private storage and PostgreSQL boundary

Nine service-only tables hold `arios_state`, `arios_settings`, `arios_profiles`, `arios_drafts`, `arios_telegram_links`, `arios_link_codes`, `arios_telegram_updates`, `arios_locks`, and `arios_rate_limits`. Enable RLS on all; revoke table and RPC privileges from PUBLIC, anon, and authenticated. Only the Edge service role accesses them directly. User authorization is performed in Edge before that privileged access. RPCs use controlled inputs, explicit search paths, and service-only EXECUTE privileges; do not broaden grants to solve a client permission problem.

Use revision-based compare-and-swap for domain state, and atomic RPCs for bootstrap/account commit, draft claims, one-time link codes, inbox ingestion, locks, and rate limits. Retry conflicts rather than losing another writer's report. Do not make external calls inside callbacks that may be repeated. Preserve checks and unique constraints for one state row, one Telegram identity/account, one consumed code, and one update/draft/report effect.

The `arios-audio` bucket is private, with no anon/authenticated object policies. Authenticated Edge issues a signed upload URL only for a newly persisted draft owned by that caller. The path is server-generated under `voice/<domainUserId>/<draftId>.<extension>`; never trust a client-supplied path during finalization. Validate supported extension/MIME, expected size, actual server-observed size, and ownership before transcription. A signed URL is limited upload capability, not a public bucket or service key. Do not log or persist it in browser storage.

## Shared domain invariants

State has `schemaVersion:1` and arrays `users`, `projects`, `reports`, `materials`, `invoices`, `messages`, `tickets`, `inventory`, `receipts`, and `audit`. All validation failures leave persisted state unchanged. Return detached allowlisted `publicState` snapshots, never raw state/settings/password fields.

Managers manage the whole workspace. Workers see only current assigned projects and their own reports, without budgets, contracts, worker rates, material prices, finance, receipts, inventory, or audit. Customers see their own projects, published materials, invoices/receipts, permitted messages, and scoped support; never internal team messages, worker rates/reports, internal costs, inventory, or audit. Assignment changes alter current access without deleting historical records.

Money is nonnegative whole toman; elapsed work is integer minutes; material/inventory quantities have at most three decimal places. Manager project edits can change progress, status, client note, customer, and workers; customer assignment is optional. Material consumption checks matching unit and sufficient stock atomically. Inventory supports validated zero starting quantity. Payments are manual receipts only, rejecting duplicate references, overpayments, and fractional money. No online payment success or banking verification is claimed.

Report creation is worker/self or manager/assigned-worker only. Validate real ISO date, HH:MM range with end after start, and integer break shorter than duration. Capture historical hourly rate; submitted labor cost is zero. Report correction requires the current version, ownership/manager permission, current valid membership, and an unapproved report; resubmit the same record. Keep rate when work date is unchanged and select historical rate again when date changes. Approved records are immutable; repeated identical approval is idempotent. Manager approval rejects overlapping approved intervals for the same worker/date across projects and computes rounded labor cost once. Transcription and draft creation never approve or charge labor.

Messages, tickets, replies, and status changes remain project-scoped. Customers cannot create internal messages. Project AI gets only minimal authorized operational context without unrelated projects, rates, or finance. Escalation creates one scoped support ticket for an identical request; the model does not execute arbitrary business actions.

## Voice and Telegram workflow

Safe API shape remains compatible with the portal: session has `authMode:'supabase'`, `demo:false`, safe `user`, and capability flags; `/api/state`, `/api/actions`, and `/api/assistant` return scoped results. Voice is available only to workers/managers. `/api/voice` returns permitted drafts and nonsecret integration/Telegram metadata. Customers cannot access voice, and workers cannot configure integrations or advance the shared Telegram inbox.

Manager `/api/integrations` accepts only dedicated AvalAI or OpenAI `/v1` origins, bounded model/key fields, and a dedicated Telegram token. A provider change requires its matching new key. Verify bot identity and `getWebhookInfo`; reject an existing webhook, never delete it. Rotate only the same bot's token after history exists. Credentials live in service-only `arios_settings`; responses expose flags, model/origin, and bot metadata only. The unavailable legacy D1 encryption key must not be invented or silently bypassed by using another project's key.

`/api/telegram/link` generates a hashed ten-minute one-time code for self or manager-selected member. Consume only a private-chat `/start CODE` from a real nonbot sender; usernames/display names are not identity. Link/unlink are atomic and authorized. `/api/telegram/sync` receives only incoming messages; do not send Telegram messages without separate user authorization. Persist unique updates before advancing the cursor, use bounded inbox locks and draft leases, recover expired claims, and avoid duplicate reports on replay.

`/api/voice/upload-url` issues the scoped signed upload; browser uploads directly to that URL and then calls `/api/voice/upload-complete {id}`. `/api/voice/text`, `/api/voice/retry`, and `/api/voice/submit` remain scoped to owner or manager. Final submission revalidates all fields, fixes a linked worker as report owner, creates at most one report, and returns canonical persisted report data. Status is pending/processing/ready/failed/submitted, source Telegram/upload/text.

Use fixed Telegram API and download origins, safe file paths, explicit deadlines, bounded streaming/response bodies, and the 20 MiB limit. `redirect:'manual'` plus explicit 3xx rejection prevents forwarding credentials. Telegram tokens appear in URLs; never return raw URLs or network errors. Persian OGG transcription is multipart and needs no manual format conversion.

Treat transcript/project text as untrusted data. Extract nullable unknown project/date/time/break values, description, output, and warnings. Do not invent work hours or calendar dates; today is a Tehran reference only when explicitly mentioned. Preserve transcript before extraction so retry does not re-transcribe. Uploaded raw audio stays private for retry, is removed after transcript checkpoint, and is cleaned in bounded sync/upload runs when untranscribed for seven days. Recheck completed signed-upload paths after token expiry to remove recreated remnants. This is bounded opportunistic cleanup, not a claimed cron service.

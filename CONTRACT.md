# ARIOS implementation contract — v0.4

## Isolation and truthful deployment state

ARIOS is an independent project. Never access or reuse Doctor Man files, databases, environment credentials, node_modules, accounts, services, or deployment configuration. Existing unrelated injected variables are not ARIOS configuration. Use dedicated ARIOS resources. Real keys, bot tokens, passwords, bootstrap codes, sessions, signed upload URLs, databases, and runtime records must never enter tracked source, public bundles, browser storage, logs, source archives, or task prompts.

The dedicated Supabase project is `arios-os`, ref `qategfabulrkvdckzmqp`. Its PostgreSQL schema, private Storage bucket `arios-audio` (20 MiB), and Edge Function `arios-api` are provisioned; the function is ACTIVE. Legacy D1 production data migration imported one state row, one draft, and one Telegram link. Do not infer that imported links configure the bot. The previous D1 integration-encryption key was unavailable; encrypted integration settings were not recoverable and must be entered again through the secure manager form after owner bootstrap. Never import fictional browser-local demo data automatically.

The real source is hosted at `https://github.com/Amirshafieisoork/Arios`, with the original Git history preserved. The Vercel project is `arios` under team `drman`; its primary production domain is `https://arios-rouge.vercel.app`. A prior deployment and Supabase health response were verified. Every new release still needs its exact pushed commit, terminal deployment result and live API verification; local build success does not prove publication.

Preserve the existing Sites identity and URL (`https://arios-os-workspace.ivorymaple.chatgpt.site`) as a fallback. Root owns publication and does not silently replace either host or the dedicated Supabase project.

## Public entry, authentication, and bootstrap

The Site is public, but operational records and actions require a valid Supabase Auth session and private ARIOS profile. Entry paths are `/`, `/login/client`, `/login/team`, `/setup`, and `/portal/`. There is no ChatGPT sign-in requirement in the current ARIOS login flow, no public self-registration, and no nonfunctional password-reset button.

`POST /api/login` accepts a contact phone or username and password, while preserving legacy email login. Normalize Persian/Arabic digits and Iranian/international phone formats consistently. Resolve existing phone/username identities privately; new phone accounts use an internal Auth email alias that is neither a contact email nor a message destination. Never expose that alias or an identity-to-account lookup to anonymous callers. Password creation accepts 6–128 characters without required character classes. Warehouse accounts require a distinct normalized username. Only a verified Auth user with valid ARIOS membership receives cookies; portal selection does not grant a role, and the verified role determines the destination.

Client JavaScript checks are not authorization. Access and refresh tokens are stored as HttpOnly, SameSite=Lax cookies, Secure on HTTPS; never localStorage. BFF refreshes an expired access token once through Supabase and clears invalid sessions. All BFF POSTs require the exact same Origin and reject cross-site requests. Logout clears local cookies even if remote revocation is temporarily unavailable.

Every Edge operational call validates the supplied user token through Supabase Auth and resolves role/domain identity from private `arios_profiles` plus current domain state. Never authorize from editable `user_metadata`. Public/publishable access does not grant direct table privileges. A user with a valid Auth identity but no matching ARIOS profile is denied.

Initial owner setup uses `/setup#code=...`; the actual one-time code is delivered privately and never committed. The setup script retains it only in memory and removes the URL fragment. `/api/bootstrap` is the deliberate prelogin exception: rate-limited, validated against a private hashed unexpired owner code and exact owner email, and atomically consumed. It creates or binds the Supabase owner identity to the existing manager without replacing migrated production records. No GET URL query carries a password or bootstrap code. New member/customer accounts are created only by an authenticated manager, with consistent Auth/profile/domain commits and recovery for uncertain outcomes.

Managers can edit names, contact phones, usernames and the assignable worker/customer/warehouse/accountant roles. The manager role remains protected. Switching roles updates the protected profile and domain state atomically, retains the same account ID and preserves existing reports, financial records and project history. Do not grant self-service role changes or create duplicate accounts to change a role. No invitation email or SMS is sent by this account flow.

Legacy domain-only staff records remain editable and archivable without inventing an Auth identity or changing any password. Manager snapshots derive `loginEnabled` and `loginNeedsReview` from protected profile links; these flags are not authorization data and Auth UUIDs never enter the snapshot. Manager-only `account.activate` explicitly creates a login for the same existing domain ID with a contact phone, optional username (required for warehouse), and a new 6–128 character password. Preserve rates, projects and report/finance history; never match an existing Auth identity by display name or user-editable metadata. Apply `20261023033800_arios_legacy_account_updates.sql` before publishing the associated Edge code.

Manager-only `account.archive` removes an account from active lists and blocks its application access, while preserving identity and historical records; `account.restore` reactivates the same account. Never hard-delete report/finance history or authorize an archived user with an otherwise valid JWT. Manager/self archival is forbidden. Creating another account with an archived identity must direct the manager to restore the existing account.

Anonymous `POST /api/password-reset/request` accepts one identifier, is rate-limited globally and per normalized identity, and returns an identical acknowledgement for known/unknown accounts. It records only known active accounts in a locked, bounded private queue. Manager-only `GET /api/password-reset/requests` lists pending requests. After independently verifying the person, the manager uses `account.password.reset` to set a 6–128 character password through Supabase Auth Admin; never store/echo passwords. This is manager-assisted recovery, with no claimed SMS/email delivery. The owner-manager is protected and uses the official Auth dashboard recovery path. A private reset cutoff plus a read-only matching Auth session check rejects pre-reset access and refresh sessions. The narrowly scoped SECURITY INVOKER RPC reads only session id/user id/created_at and is executable only by service_role.

There is no anonymous operational-data or sync exception. The deliberate public routes are the allowlisted project gallery and public service assistant; neither returns private state. `/api/telegram/sync` requires an authenticated ARIOS manager. No permanent webhook or background schedule is implemented; browser manager polling is not unattended receipt. Any future unattended integration needs its own explicit scoped authorization and verification before scheduling.

## Private storage and PostgreSQL boundary

Nine service-only tables hold `arios_state`, `arios_settings`, `arios_profiles`, `arios_drafts`, `arios_telegram_links`, `arios_link_codes`, `arios_telegram_updates`, `arios_locks`, and `arios_rate_limits`. Enable RLS on all; revoke table and RPC privileges from PUBLIC, anon, and authenticated. Only the Edge service role accesses them directly. User authorization is performed in Edge before that privileged access. RPCs use controlled inputs, explicit search paths, and service-only EXECUTE privileges; do not broaden grants to solve a client permission problem.

Use revision-based compare-and-swap for domain state, and atomic RPCs for bootstrap/account commit, draft claims, one-time link codes, inbox ingestion, locks, and rate limits. Retry conflicts rather than losing another writer's report. Do not make external calls inside callbacks that may be repeated. Preserve checks and unique constraints for one state row, one Telegram identity/account, one consumed code, and one update/draft/report effect.

The `arios-audio` bucket is private, with no anon/authenticated object policies. Authenticated Edge issues a signed upload URL only for a newly persisted draft owned by that caller. The path is server-generated under `voice/<domainUserId>/<draftId>.<extension>`; never trust a client-supplied path during finalization. Validate supported extension/MIME, expected size, actual server-observed size, and ownership before transcription. A signed URL is limited upload capability, not a public bucket or service key. Do not log or persist it in browser storage.

`POST /api/voice/audio {id}` authorizes the current owner or manager before issuing a signed read URL. Validate the observed object, exact bucket/path and dedicated origin; the URL lasts at most five minutes and never outlives audio retention. Draft list responses contain safe availability/expiry metadata, not a stored path, Telegram file ID, bot URL or signed URL. The client keeps a playback URL only in its mounted player and clears it on navigation/logout.

## Shared domain invariants

State has `schemaVersion:1` and arrays `users`, `projects`, `reports`, `materials`, `invoices`, `messages`, `tickets`, `inventory`, `receipts`, and `audit`. All validation failures leave persisted state unchanged. Return detached allowlisted `publicState` snapshots, never raw state/settings/password fields.

Managers manage the whole workspace. Workers see current assigned projects and their own daily reports; explicitly configured project reviewers may additionally read scoped operational evidence for that project, while former reviewers retain only their frozen assigned submission evidence. Review access never grants execution writes. Workers have no budgets, contracts, worker rates, material prices, finance, receipts, full inventory records, or audit; their stock catalog contains only id/name/unit/quantity. Warehouse users see inventory and project material movements plus minimal project identifiers/names/types/status, without client contacts, work reports, invoices, messages, support or system settings. Accountants see the project/worker financial context, reports, invoices, receipts and stock valuation needed for accounting, without account administration, integration settings, project messages/support or inventory mutation. Customers see their own projects, published materials, invoices/receipts, permitted messages, and scoped support; never internal team messages, worker rates/reports, internal costs, inventory, or audit. Assignment changes alter current access without deleting historical records.

Money is nonnegative whole toman; elapsed work is integer minutes; material/inventory quantities have at most three decimal places. Manager project edits can change progress, status, client note, customer, and workers; customer assignment is optional. `inventory.create`/`inventory.receive` are manager/warehouse only and support validated zero starting quantity. `material.consume` is manager/warehouse or a worker currently assigned to that project; stock identity/unit/price are canonical and sufficient stock is checked atomically. Workers cannot choose prices or publish customer costs. `material.return` cannot exceed remaining consumed quantity, precede the consumption date, or return an independent non-stock item. Returns replenish stock, preserve original quantity and append a ledger; `quantity` is net project consumption so financial totals reflect returns. Payments are manual manager/accountant receipts only, rejecting duplicate references, overpayments, and fractional money. No online payment success or banking verification is claimed.

Report creation is worker/self or manager/assigned-worker only. Validate real ISO date, HH:MM range with end after start, and integer break shorter than duration. Capture historical hourly rate; submitted labor cost is zero. Report correction requires the current version, ownership/manager permission, current valid membership, and an unapproved report; resubmit the same record. Keep rate when work date is unchanged and select historical rate again when date changes. Approved records are immutable; repeated identical approval is idempotent. Manager approval rejects overlapping approved intervals for the same worker/date across projects and computes rounded labor cost once. Transcription and draft creation never approve or charge labor.

Messages, tickets, replies, and status changes remain project-scoped. Customers cannot create internal messages. Project AI gets only minimal authorized operational context without unrelated projects, rates, or finance. Escalation creates one scoped support ticket for an identical request; the model does not execute arbitrary business actions.

Public project publication is explicit and off by default. `GET /api/public-projects` selects only `publicVisible:true` projects with an explicit public title and returns an allowlist of public title, summary, type, status, progress and a controlled illustrative cover. Never expose private project names as an automatic fallback, addresses, customers, members, reports or financial values. Generated service imagery is conceptual, not evidence of completed customer work.

The public assistant uses only fixed public company/service information. Bound message/history sizes and durable global/visitor usage limits. If the provider is unavailable, a useful fixed service guide may respond with `live:false` and `mode:'guide'`; the UI must label that mode honestly. Authenticated no-project assistance must not invent project context or create an unscoped support ticket.

## Voice and Telegram workflow

Safe API shape remains compatible with the portal: session has `authMode:'supabase'`, `demo:false`, safe `user`, and capability flags; `/api/state`, `/api/actions`, and `/api/assistant` return scoped results. Voice is available only to workers/managers. `/api/voice` returns permitted drafts and nonsecret integration/Telegram metadata. Customers cannot access voice, and workers cannot configure integrations or advance the shared Telegram inbox.

Manager `/api/integrations` accepts only dedicated AvalAI/OpenAI `/v1` bases or Groq `https://api.groq.com/openai/v1`, bounded model/key fields, and a dedicated Telegram token. A provider change requires its matching new key. Groq defaults are `openai/gpt-oss-20b` for report/chat and `whisper-large-v3-turbo` for transcription; free-plan access is quota-limited and actual account/model eligibility must be verified. There is no silent provider or paid fallback. Verify bot identity and `getWebhookInfo`; reject an existing webhook, never delete it. Rotate only the same bot's token after history exists. Credentials live in service-only `arios_settings`; responses expose flags, model/origin, and bot metadata only. The unavailable legacy D1 encryption key must not be invented or silently bypassed by using another project's key.

Manager-only `POST /api/integrations/test` separately checks chat/report generation and transcription with a bounded short prompt and synthetic one-second WAV. Return stage `ok`, fixed safe `message`, error `code`, optional provider HTTP status and a fixed allowlisted provider reason; never return raw provider text or credentials. Preserve the configured provider: an OpenAI failure does not authorize sending its key or user audio to another provider. Provider failures distinguish authentication, quota, unsupported model/format, timeout and invalid output. A saved key is not proof of a working connection.

`/api/telegram/link` generates a hashed ten-minute one-time code for self or manager-selected member. Consume only a private-chat `/start CODE` from a real nonbot sender; usernames/display names are not identity. Link/unlink are atomic and authorized. `/api/telegram/sync` receives only incoming messages; do not send Telegram messages without separate user authorization. Persist unique updates before advancing the cursor, use bounded inbox locks and draft leases, recover expired claims, and avoid duplicate reports on replay.

`/api/voice/upload-url` issues the scoped signed upload; browser uploads directly to that URL and then calls `/api/voice/upload-complete {id}`. `/api/voice/text`, `/api/voice/retry`, and `/api/voice/submit` remain scoped to owner or manager. Final submission revalidates all fields, fixes a linked worker as report owner, creates at most one report, and returns canonical persisted report data. Status is pending/processing/ready/failed/submitted, source Telegram/upload/text.

Use fixed Telegram API and download origins, safe file paths, explicit deadlines, bounded streaming/response bodies, and the 20 MiB limit. `redirect:'manual'` plus explicit 3xx rejection prevents forwarding credentials. Telegram tokens appear in URLs; never return raw URLs or network errors. Persian OGG transcription is multipart and needs no manual format conversion.

Treat transcript/project text as untrusted data. Extract nullable unknown project/date/time/break values, description, output, and warnings. Do not invent work hours or calendar dates; today is a Tehran reference only when explicitly mentioned. Preserve transcript before extraction so retry does not re-transcribe. Upload and Telegram originals remain private and playable for seven days from receipt, including after transcription, failure or submission. Cache existing recent Telegram originals lazily on first playback. Bounded cleanup removes expired objects while preserving transcripts/reports and active processing claims; this is opportunistic cleanup, not a claimed cron service.

## Digital project dossier and six-stage approval

New projects require a manager-entered unique normalized project code, an active project responsible, and all six ordered reviewer assignments: project responsible, unit responsible, technical group manager, sales, finance, CEO. Repeated account IDs are valid; responsibility labels and separate approvals remain distinct. Existing projects are not assigned invented codes or reviewers. Manager configuration edits apply to future submissions, never to frozen pending approvals.

Daily work reports retain the existing manager review/payroll rules. The aggregate project dossier combines dated work evidence, net material consumption/returns and a separate financial worksheet. Submitting creates a detached allowlisted snapshot with its own id, version, six-stage route and audit history. Later source reports, stock returns, project edits, names and worksheet edits must not silently alter that submitted evidence. An approval is an authenticated application action, not a claimed handwritten or cryptographic signature.

Each review requires the current submission id/version and the active current reviewer. A single action advances exactly one stage, even when the next stage belongs to the same person. Returns/rejections require a note. Resubmission starts a fresh six-stage cycle and preserves prior evidence. Only final approval is labeled complete; dossier approval never creates payroll, receipts, bank payments or invoices. Finance roles may start an explicit new revision of a terminal dossier with a recorded reason; prior snapshots remain immutable. Revision archive limits fail explicitly rather than discarding approval evidence.

Only managers may reassign the pending stage with an explicit reason and expected version; preserve completed stages and record both identities. Archived/inactive reviewers cannot approve. Configured reviewers gain scoped read access without tasks, messages, tickets or upload/mutation rights. Private financial fields and worksheet allocations remain restricted to manager/accountant roles in snapshots, print output and action responses. Reviewer-only file downloads are limited to authorized report photo IDs; global accountant financial read access alone does not grant private file access. Raw voice drafts stay private to their existing owner/manager policy.

The worksheet records quantities/unit wages, declared/agreed wage and staff wage/bonus/manual payment references separately from actual hourly payroll. An entered paid amount requires an entered payment date/reference; the application does not claim banking verification. Printable reports use Arios branding and actual authorized project data. Sample names, phones, codes and the other company's logo from the uploaded paper form are not seed data.

The normal state response contains dossier descriptors only (identity, status, current stage and count), keeping archived evidence out of bulk responses. Authenticated `POST /api/project-dossiers/read {projectId,id}` resolves the canonical active actor and authorizes the exact selected current/archive record before returning a detached allowlisted snapshot. Never substitute live data while a frozen document is loading or unavailable. Frontend document caches are scoped by actor/role, project policy, id and version, invalidated on account transitions, and protected against stale asynchronous responses. Source snapshots and control audit have explicit size limits below the hosted response boundary; reject oversized submissions without truncating evidence. Actual completion date/notes are independent from planned delivery and captured in the frozen operational summary.

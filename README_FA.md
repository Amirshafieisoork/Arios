# آریوس — ARIOS OS ۰.۲

فضای کار فارسی و راست‌به‌چپ برای مدیریت پروژه، تیم اجرایی، مشتری و گزارش کار. نسخهٔ میزبانی‌شده از سرور Worker، پایگاه دادهٔ ماندگار D1 و فضای فایل خصوصی R2 استفاده می‌کند.

آریوس مستقل است: هیچ کد، پایگاه داده، حساب، کلید، پوشهٔ وابستگی یا سرویسی از پروژهٔ «دکتر من» استفاده نمی‌شود. فقط اتصال‌ها و متغیرهای اختصاصی `ARIOS_*` به آریوس تعلق دارند.

## شروع کار در نسخهٔ میزبانی‌شده

۱. مالک با حساب ChatGPT مجاز وارد سایت می‌شود. ایمیل مالک باید در `ARIOS_OWNER_EMAIL` تنظیم شده باشد. در اولین ورود، فضای کار با یک مدیر و فهرست‌های خالی ساخته می‌شود؛ نام‌ها، مبالغ و گزارش‌های نسخهٔ نمونه به داده‌های واقعی منتقل نمی‌شوند.

۲. در «نیروها و همکاران»، اعضای تیم و مشتریان را با ایمیل حساب ChatGPT خودشان اضافه کنید. پروژه بسازید، نیروها و در صورت نیاز مشتری را به آن تخصیص دهید و نرخ ساعتی نیروها را با تاریخ اثر ثبت کنید. پروژه می‌تواند ابتدا بدون مشتری ساخته شود؛ اعضا و مشتری بعداً قابل تغییرند.

۳. در «ویس و گزارش هوشمند»، «تنظیم اتصال‌ها» را باز کنید. سرویس AvalAI یا OpenAI، کلید اختصاصی آریوس، مدل ساخت گزارش و مدل تبدیل گفتار را وارد کنید. نمونهٔ مدل‌های قابل تنظیم `gpt-4o-mini` و `whisper-1` هستند؛ دسترسی حساب ارائه‌دهنده به مدل انتخابی باید برقرار باشد. تغییر سرویس به کلید اختصاصی همان سرویس نیاز دارد.

۴. برای دریافت از تلگرام، توکن بات اختصاصی آریوس را در همان فرم وارد کنید. برنامه هویت بات و وضعیت وب‌هوک آن را بررسی می‌کند. اگر بات وب‌هوک دیگری داشته باشد، اتصال رد می‌شود؛ برنامه وب‌هوک موجود را حذف نمی‌کند. برای این مسیر از بات اختصاصیِ بدون وب‌هوک استفاده کنید.

۵. «اتصال حساب عضو تیم» یا «اتصال حساب من» را بزنید. عضو باید دستور `/start CODE` را با کد یک‌بارمصرف نمایش‌داده‌شده در گفت‌وگوی خصوصی بات بفرستد. کد ده دقیقه اعتبار دارد. مدیر سپس «همگام‌سازی تلگرام» را می‌زند تا اتصال دریافت و ثبت شود. اتصال بر اساس شناسهٔ تلگرام و حساب آریوس است، نه نام نمایشی یا نام کاربری تلگرام.

۶. عضو ویس را در گفت‌وگوی خصوصی بات می‌فرستد. با همگام‌سازی مدیر، صوت دریافت و به متن و پیش‌نویس گزارش تبدیل می‌شود. بارگذاری مستقیم فایل صوتی یا ورود متن از همین صفحه هم ممکن است. سقف فایل صوتی ۲۰ مگابایت است و فرمت OGG ویس تلگرام بدون تبدیل دستی پذیرفته می‌شود.

۷. در صندوق پیش‌نویس‌ها، متن اصلی را با گزارش مقایسه کنید. پروژه، تاریخ، ساعت شروع و پایان، استراحت، شرح فعالیت و نتیجه را بررسی و بخش‌های نامشخص را تکمیل کنید. «ثبت و ارسال برای بررسی مدیر» گزارش را ثبت می‌کند؛ هزینهٔ دستمزد فقط بعد از تأیید مدیر محاسبه می‌شود. درخواست تکراری گزارش تکراری نمی‌سازد.

افزودن ایمیل به آریوس به‌تنهایی دسترسی میزبانی Sites را باز نمی‌کند. برای ورود اعضا، مالک باید آن‌ها را جداگانه در سیاست دسترسی سایت مجاز کند. سطح دسترسی نقش و پروژه همچنان در سرور آریوس کنترل می‌شود.

## دریافت تلگرام و اجرای خودکار

این اتصال فقط دریافت‌کننده است و پیام خروجی برای کاربران تلگرام نمی‌فرستد. مدیر با دکمهٔ همگام‌سازی دریافت را اجرا می‌کند؛ هنگام باز بودن صفحهٔ ویس برای مدیر، هر ۳۰ ثانیه دریافت بررسی می‌شود. صفحهٔ نیرو وضعیت پیش‌نویس‌های همان نیرو را تازه می‌کند. بررسی خودکار هنگام باز بودن فرم ویرایش، انتخاب فایل یا نوشتن متن متوقف می‌شود تا ورودی از دست نرود.

باز بودن صفحه برای دریافت دائمی کافی نیست. مسیر خصوصی `POST /api/telegram/sync` برای اجرای بدون حضور کاربر هم آماده شده است، اما تنها با `ARIOS_PRIVATE_SERVICE_SYNC=1` و پشت مرز دسترسی خصوصی Sites قابل استفاده است. کار سرویس باید مجوز معتبر همان سایت را در هدر `OAI-Sites-Authorization` داشته باشد؛ درخواست سرویس فاقد هویت مرورگر و هدر `Origin` است. این قابلیت نباید روی سایت عمومی یا پس از تغییر مخاطبان بدون بازبینی مجوز فعال بماند.

در این نسخه کار زمان‌بندی‌شده‌ای ایجاد نشده و دریافت خودکار هنگام بسته بودن صفحه فعال نیست. این قابلیت فقط پس از ایجاد و آزمون یک کار زمان‌بندی‌شدهٔ متصل به سایت برقرار می‌شود؛ رازها نباید در متن دستور آن قرار بگیرند. آزمون زندهٔ مسیر سرویس از محیط توسعه با محدودیت شبکهٔ `CONNECT 403` به نشانی سایت متوقف شده است؛ وجود مسیر خصوصی یا موفقیت انتشار به‌تنهایی تأیید اجرای بدون حضور کاربر نیست.

## داده‌ها، خطا و نگه‌داری صوت

- گزارش‌ها، پروژه‌ها، پیش‌نویس‌ها، اتصال حساب‌ها و شناسه‌های پیام تلگرام در D1 ذخیره می‌شوند و میان دستگاه‌ها مشترک‌اند.
- شناسهٔ یکتای پیام، نشانگر دریافت و قفل پردازش مانع دریافت و ثبت تکراری می‌شوند. شکست تبدیل در صندوق پیش‌نویس‌ها نمایش داده می‌شود و امکان تلاش دوباره دارد.
- فایل بارگذاری‌شده در R2 خصوصی نگه داشته می‌شود تا شکست رونویسی قابل تلاش دوباره باشد. پس از ذخیرهٔ متن رونویسی، فایل خام بارگذاری‌شده حذف می‌شود؛ متن برای ساخت دوبارهٔ گزارش باقی می‌ماند.
- فایل‌های بارگذاری‌شدهٔ بدون متن که بیش از هفت روز قدمت دارند، در نوبت‌های محدود پاک‌سازی هنگام همگام‌سازی یا بارگذاری بعدی حذف می‌شوند. پس از پایان این مهلت باید فایل را دوباره بارگذاری کرد.
- فایل تلگرام در تلاش دوباره از API تلگرام دریافت می‌شود. پیوند دانلود یا توکن بات در پاسخ عمومی و خطای کاربر نمایش داده نمی‌شود.
- صوت و متن برای تبدیل به ارائه‌دهندهٔ انتخاب‌شده توسط مدیر فرستاده می‌شود. فقط پروژه‌های مجاز همان فرستنده برای انتخاب پروژه در اختیار گزارش‌ساز قرار می‌گیرد. ساعت و تاریخ نامعلوم به‌عنوان اطلاعات قطعی ثبت نمی‌شود.
- توکن بات و کلید ارائه‌دهنده فقط در فرم امن مدیر وارد می‌شوند؛ آن‌ها را در چت، سورس، خروجی داده‌ها یا حافظهٔ محلی مرورگر قرار ندهید. تنظیمات محرمانه در D1 با AES-GCM و راز runtime اختصاصی رمز می‌شوند. پاسخ API فقط وضعیت اتصال و تنظیمات غیرمحرمانه را برمی‌گرداند.

## سایر قابلیت‌ها

مدیر پروژه و اعضا را مدیریت می‌کند، پیشرفت و یادداشت مشتری را ثبت می‌کند، گزارش‌ها را بررسی می‌کند و موجودی، مصرف تجهیزات، صورت‌حساب و رسید دستی را نگه می‌دارد. نیروی اجرایی فقط پروژه‌های تخصیص‌یافته و گزارش‌های خودش را می‌بیند. مشتری فقط پروژه‌ها، اقلام منتشرشده، صورت‌حساب‌ها و پیام‌های مجاز خودش را می‌بیند.

گزارشِ نیازمند اصلاح، ردشده یا هنوز تأییدنشده با کنترل نسخه قابل اصلاح و ارسال دوباره است. گزارش تأییدشده تغییر نمی‌کند. نرخ تاریخی در گزارش ثبت می‌شود و گزارش‌های زمانی هم‌پوشان همان نیرو هنگام تأیید رد می‌شوند. کالاهای جدید حتی با موجودی صفر قابل تعریف و سپس تأمین‌اند.

دستیار پروژه با اتصال اختصاصی هوش مصنوعی فعال می‌شود و فقط زمینهٔ مجاز همان پروژه را دریافت می‌کند. برای مسئلهٔ نیازمند بررسی انسانی، تیکت همان پروژه ایجاد می‌کند؛ درخواست یکسان تیکت تکراری نمی‌سازد. پیام داخلی تیم برای مشتری نمایش داده نمی‌شود.

پرداخت آنلاین متصل نیست. رسید پرداخت واقعی فقط به‌صورت دستی توسط مدیر ثبت می‌شود؛ برنامه پرداخت موفق ساختگی یا تأیید بانکی بدون درگاه تولید نمی‌کند.

## ساخت و انتشار Worker

پیش‌نیاز توسعه: Node.js 24. وابستگی‌های ساخت باید در پوشهٔ اختصاصی همین پروژه نصب شوند.

```bash
npm ci --no-audit --no-fund
npm test
npm run build
```

فرمان `build` از `worker/index.mjs`، منطق مشترک و فایل‌های `public` خروجی `dist/server/index.js` می‌سازد. دارایی‌ها در Worker بسته‌بندی می‌شوند. `.openai/hosting.json` همان شناسهٔ سایت و اتصال‌های `d1: "DB"` و `r2: "BUCKET"` را حفظ می‌کند؛ نسخهٔ hosted خروجی ایستای نمایشی نیست.

طرح پایگاه داده در `db/schema.ts` است. فقط پس از تغییر طرح، مهاجرت جدید تولید و بررسی کنید:

```bash
npm run db:generate
```

فایل‌های SQL و فرادادهٔ `drizzle` همراه سورس ثبت و به `dist/.openai/drizzle` کپی می‌شوند. مهاجرت‌های اعمال‌شده را تغییر ندهید؛ برای تغییر بعدی مهاجرت جدید بسازید. انتشار از مسیر رسمی Sites، مهاجرت‌ها و اتصال منابع را اعمال می‌کند. `npm run build` به‌تنهایی چیزی را منتشر نمی‌کند.

تنظیمات runtime نسخهٔ hosted از ابزار تنظیم متغیرهای Sites اعمال می‌شوند؛ فایل `.env` محلی به‌صورت خودکار به Worker میزبانی‌شده منتقل نمی‌شود:

| متغیر | کاربرد |
| --- | --- |
| `ARIOS_OWNER_EMAIL` | ایمیل مالک برای راه‌اندازی اولیهٔ فضای کار خالی |
| `ARIOS_ENCRYPTION_KEY` | راز Base64 شامل ۳۲ بایت تصادفی، برای رمزگذاری تنظیمات؛ تغییر بی‌برنامهٔ آن تنظیمات قبلی را ناخوانا می‌کند |
| `ARIOS_AI_BASE_URL` | اختیاری؛ `https://api.avalai.ir/v1` یا `https://api.openai.com/v1` |
| `ARIOS_AI_API_KEY` | راز اختیاری؛ کلید اختصاصی ارائه‌دهنده |
| `ARIOS_AI_MODEL` | اختیاری؛ مدل ساخت گزارش و دستیار |
| `ARIOS_TRANSCRIPTION_MODEL` | اختیاری؛ مدل تبدیل گفتار؛ پیش‌فرض `whisper-1` |
| `ARIOS_TELEGRAM_BOT_TOKEN` | راز اختیاری؛ توکن اختصاصی بات |
| `ARIOS_PRIVATE_SERVICE_SYNC` | فقط برای سایت تأییدشدهٔ خصوصی: مقدار `1` مسیر همگام‌سازی سرویس را فعال می‌کند؛ پیش‌فرض غیرفعال |

مقادیر ارائه‌دهنده و بات را می‌توان از فرم مدیر تنظیم کرد؛ مقدار runtime هم‌نام بر تنظیم ذخیره‌شدهٔ فرم اولویت دارد. تغییر توکن به بات دیگری پس از ایجاد سابقه پذیرفته نمی‌شود؛ تعویض توکن همان بات مجاز است. هویت کاربر از ورود ChatGPT در Sites گرفته و به حساب آریوس متصل می‌شود؛ Worker ورود رمز عبوری جداگانه ایجاد نمی‌کند.

## سرور مستقل Node و محیط نمونه

`server.mjs` همچنان اجرای مستقل Node با SQLite، رمز عبور و نشست امن را پشتیبانی می‌کند. مسیر ویس، R2 و دریافت تلگرام در نسخهٔ Worker پیاده شده‌اند؛ اجرای Node جایگزین آن‌ها نیست.

برای محیط نمونهٔ محلی:

```bash
npm run demo
```

برای شروع سرور Node تولید، `.env.example` را به `.env` کپی کنید، فقط بخش متغیرهای Node را با اطلاعات اختصاصی آریوس تنظیم و سپس اجرا کنید:

```bash
npm start
```

`ARIOS_BOOTSTRAP_EMAIL` و `ARIOS_BOOTSTRAP_PASSWORD` فقط مدیر اولیهٔ SQLite را می‌سازند؛ رمز باید حداقل ۱۲ نویسه باشد و پس از راه‌اندازی از تنظیمات bootstrap حذف شود. برای میزبانی دوردست، HTTPS، `ARIOS_PUBLIC_ORIGIN` دقیق و دیسک پایدار SQLite لازم است. حساب ورود Node از فرم حساب مدیر ساخته می‌شود؛ ساخت پروفایل به‌تنهایی رمز ورود Node ایجاد نمی‌کند.

برای ساخت پیش‌نمایش قدیمیِ ایستا، جدا از خروجی Worker:

```bash
npm run build:preview
```

این فرمان `dist` را با اطلاعات نمونهٔ ساختگی و ذخیرهٔ محلی مرورگر جایگزین می‌کند. حساب و مدل واقعی، پایگاه دادهٔ مشترک یا دریافت ویس در این خروجی فعال نیست. داده‌های نمونه خودکار به نسخهٔ تولید منتقل نمی‌شوند. برای بازگشت به خروجی hosted دوباره `npm run build` را اجرا کنید.

`npm run package:source` با Python 3 آرشیو سورس را تولید می‌کند. بستهٔ سورس باید فقط کد، آزمون‌ها، مهاجرت‌ها و نمونهٔ تنظیمات را داشته باشد؛ رازها، داده‌های زنده، SQLite، پوشهٔ وابستگی و خروجی ساخت وارد سورس نمی‌شوند.

## آزمون‌ها

```bash
npm test
node --test --test-isolation=none tests/voice.test.mjs tests/storage.test.mjs tests/worker-flow.test.mjs tests/domain-workflows.test.mjs
npm run build
```

آزمون‌ها رونویسی OGG، محدودیت حجم، پاسخ خراب سرویس، محرمانگی خطا، استخراج محتاطانهٔ ساعت و تاریخ، کنترل دسترسی، دریافت تکراری تلگرام، کد اتصال، ثبت یکتای گزارش، retry، نگه‌داری و حذف فایل R2، رمزگذاری تنظیمات، نوشتن هم‌زمان D1، اصلاح گزارش و کنترل هزینه را بررسی می‌کنند. اتصال‌های Telegram و AI در آزمون‌ها شبیه‌سازی می‌شوند و پیام واقعی یا درخواست پولی ارسال نمی‌شود. موفقیت آزمون جای آزمون زنده با بات و کلید اختصاصی را نمی‌گیرد.
